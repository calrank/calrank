# 새 페이지 생성 기준 (2026-11-14 기준, 서치 콘솔 관찰에서 도출)

새 페이지(판정·등급·난이도·기어·코스·대회·칼럼·허브·도구)를 만들거나 생성기를 고칠 때 먼저 이 문서를 본다.
숫자 기준은 **초기값**이며, 4주 뒤 서치 콘솔 결과로 조정한다.

## 1. 근거가 된 관찰

| 관찰 | 의미 |
|---|---|
| 색인 750개(10/20) → 109개(10/24) | 대회 id 정리(별칭 748개)와 겹침. 주소가 바뀌면 색인이 한꺼번에 빠진다 |
| 대회 페이지 825개 중 색인 약 10%. 접두사·월·좌표·HTML 크기와 무관 | 구조가 같은 사본은 페이지 특성으로 가려지지 않고 표본처럼 색인된다 |
| 사이트맵 1,703개인데 서치 콘솔이 아는 URL은 약 1,190개 | 신생 도메인에서 한꺼번에 늘리면 대기열에 쌓인다 |
| 크롤링됨-색인 안 됨 677개 중 494개가 지난 대회 | 끝난 대회 페이지의 단독 가치는 낮다 |
| 색인된 일반 페이지는 가이드·칼럼·월간·랜딩 11개 | 주제가 있는 설명형 페이지는 통과한다 |
| Soft 404 17개 = 옛 id의 `event.html?id=` | 자바스크립트가 채우는 페이지가 "찾을 수 없음"을 200으로 돌려주면 Soft 404가 된다 |
| 칼럼 4개가 목록·링크에서 빠져 있었음 | 연결이 없으면 본문이 좋아도 뒤로 밀린다 |
| 누적 노출 529회, 최근 열흘 0 | 색인되어도 검색어와 맞지 않으면 노출이 없다 |

한계: 위 관찰은 상관이다. "이렇게 하면 색인된다"는 인과가 아니라 "이렇게 하면 불리했다"의 근거로만 쓴다.

## 2. 만들기 전 관문 (모두 통과해야 만든다)

1. **한 문장 과업.** "누가 어떤 검색 의도로 와서 무엇을 얻어 가는가"를 한 문장으로 적는다. 못 적으면 만들지 않는다.
2. **고유 가치 테스트.** 틀·메뉴·공통 문구를 빼고도 이 페이지에만 있는 계산, 판정, 근거가 남아야 한다. 대회마다 다른 값만 바꿔 끼운 사본은 통과하지 못한다.
3. **중복·대체 검토.** 같은 틀의 페이지가 이미 있으면 새 인스턴스를 늘리기 전에 허브나 도구 하나로 합칠 수 있는지 먼저 본다.
4. **근거.** 모든 수치·주장에 출처(논문 DOI, 공식 기관)를 붙이고 근거 등급(A~D)을 매긴다. 확인하지 못한 값은 "근거 없음"으로 두고 지어내지 않는다.
5. **재방문 이유(hook).** 읽고 끝나는 페이지인지, 내 기록·조건으로 계산하거나 이력이 쌓이는지 적는다. 둘 다 아니면 허브의 한 문단으로 흡수한다.
6. **주소 안정성.** URL 규칙을 먼저 확정한다. 이미 공개된 주소를 바꾸면 같은 변경 안에서 301(별칭)과 `event.html?id=` 같은 보조 주소의 이동까지 함께 넣는다.
7. **연결.** 공개 시점에 들어오는 내부 링크가 3개 이상이어야 한다(허브 1 + 관련 글 2 이상). 사이트맵에는 이 조건이 충족된 뒤 넣는다.

## 3. 유형별 최소 기준

| 유형 | 최소 기준 |
|---|---|
| 등급·판정 | 기준표 출처, 연령·성별 보정, 입력→결과 계산, 근거 없는 구간 표시, 한계 문구, FAQ, 구조화 데이터 |
| 기어 판정 | 동료심사 근거 1편 이상 + 등급, 조건별 적용 구간, 효과 크기·신뢰구간 또는 한계, 가격 항목은 `no_price` 규칙 준수, 갱신일 |
| 난이도·코스(산·트레일루트) | 공식 자료 출처(산림청·두루누비 등), 산 이름·지역명 본문 반영, 난이도 근거(Km-effort), 공식 영상 규칙(공식은 게시, 그 외는 "비공식 해설"), 가까운 대회·코스 연결 |
| 대회 | 좌표·거리가 있어야 색인 대상. 대회마다 다른 계산 블록 5개 이상. 후기·기록이 없는 지난 대회는 사이트맵에서 제외(종료 후 90일). 이미 색인된 페이지는 noindex로 돌리지 않는다 |
| 칼럼·가이드 | 주장마다 출처, 본문 700단어 이상, "함께 읽을 글" 3개(자동), column.html 목록 등록 |
| 허브(랜딩·월별·지역) | 지역·종목에 대한 고유 설명 + 대회·코스 링크. 대회가 적어 얇은 허브는 noindex |
| 개인화 도구 | 로그인 없이 시작, 기기 안 저장 우선, 한계·근거 표시, 공유 카드 |

## 4. 확장 속도 규칙

- 같은 틀의 새 유형은 **표본 5~10개**를 먼저 올린다. 2~4주 뒤 색인 비율을 확인하고 확장한다.
- 한 번의 푸시로 색인 대상 URL을 **50개 이상** 늘리지 않는다(초기값). 대량이 필요하면 며칠 간격으로 나눈다.
- 한 유형의 4주 색인율이 30% 아래이면 확장을 멈추고 합치기·noindex·보강 중 하나를 정한다.
- 푸시는 묶어서 한다(Vercel 배포 횟수 제한).

## 5. 출시 전 점검(자동·수동)

- `python3 scripts/sync_all.py` → `--check` 통과
- canonical 1개, robots 의도 확인, 사이트맵 반영 여부 확인
- 들어오는 링크 3개 이상(`sync_columns.py`가 칼럼·가이드를 자동 처리)
- 옛 주소가 있으면 별칭 등록과 `event.js` 이동 확인
- Playwright로 모바일(400px)·데스크톱 확인, 가로 스크롤 없음
- 출처 URL 접속 확인, 수치는 직접 다시 계산
- 영상: `check_videos.py` 통과, 공식·비공식 표시
- 문체: 판정 페이지는 전문 선언형(질문형·구어체 제목 금지)

## 6. 출시 후 측정

- 2주·4주 시점에 서치 콘솔 "색인됨 / 크롤링됨 - 색인 안 됨 / 발견됨"을 유형별로 기록한다.
- 노출·클릭이 0이면 검색어(제목·본문의 지역·산 이름·등급 용어)를 점검한다.
- 결과는 이 문서의 숫자 기준을 고치는 데 쓴다.

## 7. 하지 않는 것

- 근거 없는 수치, 직접 그린 이미지·아이콘, 구어체 제목
- 같은 틀의 사본을 한꺼번에 대량 생성
- 공개된 주소의 변경(별칭 없이)
- 사이트 소개 문구에 개별 대회 이름을 쓰는 것
- 이미 색인된 페이지를 이유 없이 noindex로 돌리거나 사이트맵에서 빼는 것 (색인 확인된 대회는 `data/indexed_events.json`에 기록하고 사이트맵에 유지한다. 서치 콘솔에서 새로 확인할 때마다 갱신)

## 8. 점검 스크립트

`python3 scripts/audit_pages.py` 가 기계로 잴 수 있는 항목(사이트맵·noindex 충돌, canonical, 들어오는 링크 3개 미만, 별칭 대상 누락, 사이트맵 누락)을 보고한다. 새 유형을 올리기 전에 돌린다.
